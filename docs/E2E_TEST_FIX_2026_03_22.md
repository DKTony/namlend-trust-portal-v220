## Overview

Fixed the failing `e2e/loan-application.e2e.ts` test by implementing proper KYC document seeding for test users and addressing timing issues with Convex reactive queries.

---

## Problem Statement

The loan application E2E test was failing with:

```
Error: expect(locator).toBeVisible() failed
Locator: getByTestId('loan-amount-input')
```

### Root Causes Identified

1. **Wrong table**: Initial seeding attempted to use `loanDocuments` instead of `kycDocuments`
2. **Schema mismatch**: Used non-existent `documentUrl` field instead of proper Convex schema fields
3. **Timing issue**: Convex reactive queries needed time to populate after login
4. **Navigation issue**: Test tried to use non-existent sidebar link for client role

---

## Solution Implemented

### 1. Fixed KYC Document Seeding Schema

**File**: `convex/seedMutations.ts`

```typescript
export const seedKycDocuments = internalMutation({
  args: {
    email: v.string(),
  },
  handler: async (ctx, { email }) => {
    const profile = await ctx.db
      .query('profiles')
      .filter((q) => q.eq(q.field('email'), email))
      .first();

    if (!profile) {
      throw new Error(`No profile found for ${email}`);
    }

    const now = Date.now();

    // Check if KYC docs already exist
    const existingDocs = await ctx.db
      .query('kycDocuments') // ✅ Correct table
      .withIndex('by_userId', (q) => q.eq('userId', profile.userId))
      .collect();

    const hasIdCard = existingDocs.some((d) => d.documentType === 'id_card');
    const hasProofIncome = existingDocs.some((d) => d.documentType === 'proof_income');

    // Create ID card document if missing
    if (!hasIdCard) {
      await ctx.db.insert('kycDocuments', {
        userId: profile.userId,
        documentType: 'id_card',
        documentNumber: 'TEST-ID-001',
        status: 'approved',
        createdAt: now,
        updatedAt: now,
      });
    }

    // Create proof of income document if missing
    if (!hasProofIncome) {
      await ctx.db.insert('kycDocuments', {
        userId: profile.userId,
        documentType: 'proof_income',
        status: 'approved',
        createdAt: now,
        updatedAt: now,
      });
    }

    // Update profile KYC status to verified
    await ctx.db.patch(profile._id, {
      kycStatus: 'verified',
      updatedAt: now,
    });
  },
});
```

**Key Changes**:

- ✅ Changed from `loanDocuments` to `kycDocuments` table
- ✅ Removed invalid `documentUrl` field
- ✅ Added proper schema fields: `documentType`, `documentNumber`, `status`, `createdAt`, `updatedAt`
- ✅ Updated profile `kycStatus` to `'verified'`

## Technical Details

### KYC Eligibility Check

The `useKYCEligibility` hook checks for two required document types:

```typescript
const REQUIRED_DOC_TYPES = ['id_card', 'proof_income'] as const;
```

Documents must have `status: 'approved'` to pass the eligibility check.

### Convex Schema

**Table**: `kycDocuments`

```typescript
kycDocuments: defineTable({
  userId: v.id('users'),
  documentType: v.string(),
  documentNumber: v.optional(v.string()),
  fileStorageId: v.optional(v.id('_storage')),
  status: v.union(v.literal('pending'), v.literal('approved'), v.literal('rejected')),
  reviewedBy: v.optional(v.id('users')),
  reviewNotes: v.optional(v.string()),
  createdAt: v.number(),
  updatedAt: v.number(),
}).index('by_userId', ['userId']);
```

### Test User Setup

After running `npx convex run seed:seedTestUsers`, the test user `client1@test.namlend.com` will have:

1. ✅ Profile with `kycStatus: 'verified'`
2. ✅ Approved `id_card` document
3. ✅ Approved `proof_income` document

This allows the test to bypass the KYC eligibility gate and test the loan application form flow.

## Lessons Learned

1. **Schema alignment is critical** - Always verify table names and field names match the Convex schema exactly
2. **Timing matters with reactive queries** - Convex reactive queries need time to populate after auth state changes
3. **Test navigation should match actual UX** - Use the same navigation paths that real users would take
4. **Logging is essential for debugging** - Detailed console logs helped identify where the seeding was failing
5. **Idempotency in seed scripts** - Check for existing data before inserting to allow safe re-runs
